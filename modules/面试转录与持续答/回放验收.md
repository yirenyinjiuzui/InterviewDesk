# 持续答双声道回放验收

2026 年 11 月 27 日在 Windows x64 上测试。改动前的三轮中，两轮因音频上传积压没有生成答案，另一轮取消了主答案，并把追问拼回主问题。最终源码连续三轮均合并了主问题和补充要求，分别给主问题和追问生成答案；“嗯”没有单独触发回答。

## 输入与计时

使用同一份 16 kHz 双声道合成录音。左声道代表面试官，右声道代表候选人。两个声道按客户端实际使用的 100 毫秒帧长、原速送入音频采集入口。在独立测试资料目录中启用持续答，使用真实的阿里云 Fun-ASR 和 DeepSeek 接口，语言设为中文。项目简历、实际面试资料和历史答题均未带入测试。[测试录音](持续答回放.wav)

| 说话人 | 内容 | 起止时间 |
| --- | --- | --- |
| 面试官 | 介绍一下你的项目。 | 3.000～4.516 秒 |
| 候选人 | 嗯。 | 4.696～5.034 秒 |
| 面试官 | 重点讲你负责的部分。 | 5.466～7.242 秒 |
| 面试官 | 你怎么验证效果？ | 9.392～10.876 秒 |

主问题从补充要求最后一个有声采样计时，追问从自身最后一个有声采样计时。终点取应用渲染帧中答案已包含首个句末标点、该句文字进入阅读区的时刻。该耗时覆盖音频上传、转录定稿、持续答判断、模型生成和界面显示。回放从音频帧入口开始，现场麦克风和扬声器的采集延迟未计入。

## 对照结果

| 版本与轮次 | 主问题到完整首句 | 追问到完整首句 | 实际行为 |
| --- | ---: | ---: | --- |
| 改前 1 | 无 | 无 | 音频上传积压，面试官问题未定稿 |
| 改前 2 | 无 | 无独立答案 | 主答案被取消；追问说完 15.12 秒后，界面渲染了合并问题的首句 |
| 改前 3 | 无 | 无 | 音频上传积压，面试官问题未定稿 |
| 改后 1 | 7.63 秒 | 6.06 秒 | 两题各答一次 |
| 改后 2 | 8.85 秒 | 5.67 秒 | 两题各答一次 |
| 改后 3 | 8.51 秒 | 6.10 秒 | 两题各答一次 |

三轮中位数为主问题 **8.51 秒**、追问 **6.06 秒**。真实服务和网络耗时会波动。原版没有分别完成两题，无法计算两道题各自的提速比例。

Windows x64 打包程序另回放一次，主问题为 **6.22 秒**，追问为 **7.21 秒**，两个答案均独立显示。此轮单列，未计入源码三轮中位数。

云端在最终三轮都把候选人的合成“嗯”识别成“文。”。另用正确的“嗯”定稿事件验证了简短应声不会打断问题，并用迟到的“文。”事件验证了先前发言不会关闭后来的追问。[问题判断回归用例](../../app/test/interviewQuestion.spec.ts) · [界面回归脚本](../../app/tools/interview-question-smoke.cjs)

## 修复范围

- 结合音频时间和问句内容识别独立追问，主问题的答案可以继续生成。紧随其后的补充要求仍可并入主问题。
- 阿里云 Fun-ASR 的实时连接使用每声道 32 kbps 的 MP3 上传，降低双路音频对上行带宽的要求。建连、任务启动、发送完末帧和等候最终定稿分别处理。[阿里云支持的音频格式](https://help.aliyun.com/zh/model-studio/real-time-speech-recognition-user-guide)
